01  认识北辰与学习方式
先认识模拟器的边界，再选择适合自己的学习方式。

语音讲解原文：
认识北辰与学习方式。欢迎使用北辰导航模拟器。本教程可以完全离线使用，每一章都有中文讲解、操作步骤和结果检查。教程只会定位界面，不会替你修改参数或发送报文。你可以先听，再按步骤操作；也可以关闭语音，只阅读文字。已有的收发任务不会因打开教程而自动停止。

详细操作：
1. 选择学习入口
   操作：点击顶部“语音教程”开始逐章学习；点击“使用说明”可搜索章节、查看全文或下载文字教程。
   应看到：右下角显示教程面板，当前章节和语音字幕清晰可见。
2. 掌握语音控制
   操作：使用播放、暂停、重播和音量控制；需要连续学习时打开“讲完自动下一章”。
   应看到：暂停后停在当前语音位置，重播从当前章开头播放。
3. 边学边操作
   操作：点击步骤旁“定位”，观察金色框所指控件；可以收起面板，再自行操作真实界面。
   应看到：定位只改变视图和高亮，不会自动触发发送。

常见问题与说明：
- 文字步骤比语音更详细，操作时以“应看到”作为检查标准。
- 切换章节不会修改你的网络或数据；关闭教程会恢复进入时的界面模式。

02  下载、运行与版本确认
完成首次运行，了解便携版、存档和兼容范围。

语音讲解原文：
下载、运行与版本确认。先确认下载的是当前版本的便携程序。单文件版本可以直接运行，压缩包版本必须完整解压，不能只拿出一个程序文件。软件自带运行环境，教程语音也已经打包，不需要联网获取中文语音。运行资源保持完整，优先保证兼容性。

详细操作：
1. 选择安装包
   操作：从当前 Release 或提供的 Drive 链接下载 Windows x64 便携 EXE；若下载 ZIP，请全部解压到本机硬盘。
   应看到：EXE 可直接启动；ZIP 目录中的程序与资源保持在一起。
2. 核对版本
   操作：查看“使用说明”标题中的版本号；下载旁的 SHA256SUMS 可用于核对安装包。
   应看到：版本应与下载文件名一致，不要混用新旧目录中的资源。
3. 了解数据保存
   操作：配置和路径可保存到本机，同时导出 JSON。重要设置请保留导出文件，再升级或换电脑。
   应看到：重新运行后可恢复本机配置，且不会自动开始发送。

常见问题与说明：
- 浏览器运行与桌面运行的本机存储相互独立。
- Windows Server 2022 的打包检查不代表所有 Windows 与麒麟机器都已实测。

03  全屏、启动声音与界面导航
学会退出全屏，区分快速测试、完整配置和协议说明。

语音讲解原文：
全屏、启动声音与界面导航。桌面版默认全屏启动，开场动画约两点五秒。按功能键十一或点击顶部全屏按钮，可以回到普通窗口。快速测试适合直接选场景，完整配置用于修改全部字段。协议约定用来查询定义，开场回看只重播动画，不重置场景。

详细操作：
1. 切换全屏
   操作：点击顶部“退出全屏”或按 F11；浏览器需要用户点击按钮才能主动进入全屏。
   应看到：桌面窗口与全屏可以来回切换。
2. 选择模式
   操作：先使用 Type 1 快速测试；需要调整姿态、惯性、状态或告警时切换 Type 2 完整配置。
   应看到：完整配置显示字段编辑区域；切换模式本身不更改数据。
3. 回看与静音
   操作：点击“开场回看”；取消开场画面的声音选项，可关闭下次自动播放声音。
   应看到：回看结束后返回原工作台，原有任务状态保留。

常见问题与说明：
- 教程语音、教程提示音与启动音各自控制。
- 浏览器首次播放声音可能需要点击播放；桌面版本允许主动播放。

04  网卡选择与共享使用
选对实际连接的 IPv4 网卡，理解网卡共享与端口冲突的区别。

语音讲解原文：
网卡选择与共享使用。顶部三种连接共用一张网卡。请选择与接收设备处在同一网络的本机地址，不要把对方设备地址填到网卡选择里。选择网卡只是确定收发来源，不会独占整张网卡，也不会更改系统网络设置。组播可以共享端口，但另一个软件也要允许复用。

详细操作：
1. 辨认本机地址
   操作：展开“共用网卡”，根据网线或无线网络实际使用的本机 IPv4 地址选择；本机回环地址只适合回环测试。
   应看到：所选地址属于本机，而不是对方接收设备。
2. 核对两端网络
   操作：确认本机与对端地址可在同一网络互通；多网卡电脑不要误选未连接的虚拟或备用网卡。
   应看到：发送记录中的来源网卡与你选择的地址一致。
3. 理解共享限制
   操作：多个软件可共用同一张网卡。若要共享组播端口，两方都需开启地址/端口复用；TCP 服务端不能共享同一监听 IP 和端口。
   应看到：端口占用错误只针对某个端口，不代表整张网卡被占用。

常见问题与说明：
- 修改网卡或连接设置会重新建立收发连接，连续任务中操作前应先暂停。
- 本机可同时运行其他网络应用，组播收包仍取决于交换机、路由和防火墙。

05  UDP 组播：一份数据给多个接收端
设置组播地址和端口，完成本机环回接收。

语音讲解原文：
用户数据报协议 组播：一份数据给多个接收端。组播适合把同一条导航报文送给多个接收端。默认组播地址是二二四点一百点一百点一，端口六零二零。两端必须使用相同的组播地址与端口，接收端还需要加入组播组。软件打开本机环回，因此自己发出的组播也可以在报文流中看到。

详细操作：
1. 开启组播
   操作：勾选 UDP 组播；将地址设置为 224.100.100.1，端口设置为 6020，或填写联调双方约定值。
   应看到：状态栏出现当前组播目标；配置正确时没有加入组播失败提示。
2. 设置接收端
   操作：在对方软件上选择实际网卡，并加入同一组播地址和端口。不要把组播当作普通单播地址使用。
   应看到：对方开始监听后，可以收到同一组播组内的导航数据。
3. 单次验证
   操作：选择“协议示例原句”，先不要启用系统时间或运动，再点击“发送一次”。
   应看到：报文流出现发送记录；组播环回正常时还会出现接收记录。

常见问题与说明：
- 仅仅能在本机环回收到，并不能证明对端已经收到。
- 修改为普通单播地址后，组播加入可能失败；单播应使用独立的 UDP 单播配置。

06  UDP 单播：精确发送到一个对端
配置独立单播目标，也可与组播同时发送。

语音讲解原文：
用户数据报协议 单播：精确发送到一个对端。单播是把数据直接送到一个设备的地址和端口。这里填写的是对方地址，不是本机网卡地址。单播、组播和传输控制协议可以独立启用，也可以同时开启；发出的内容是同一句导航报文。单播没有连接握手，发送记录并不等于对方已经确认收到。

详细操作：
1. 填写单播目标
   操作：勾选 UDP 单播，将对端地址改为接收设备 IPv4，端口改为对方实际监听端口。
   应看到：单播目标与接收端的监听配置一致。
2. 先独立验证
   操作：初次联调可先关闭组播和 TCP，仅保留单播，然后发送一次；本机测试可把对端设成本机地址并用另一个 UDP 工具监听。
   应看到：另一接收工具收到完整的 GPCHC 原文。
3. 启用多路输出
   操作：单播验证后可同时打开组播；检查发送备注中的通道列表。
   应看到：同一句报文同时经过组播和单播输出。

常见问题与说明：
- 单播配置是发送目标，不会自动在该端口新开一个单播接收服务。
- UDP 没有送达确认，请以接收端记录作为最终证据。

07  TCP 客户端：连接已有服务端
让北辰作为主动连接的一方，向已有服务端发送数据。

语音讲解原文：
传输控制协议 客户端：连接已有服务端。当接收软件已经在监听端口时，北辰应选择客户端模式。填写接收软件的地址和监听端口，再开启连接。请先看到已连接状态，再发送报文；如果界面显示无连接，发送备注里的错误不能忽略。连接会使用顶部所选的本机网卡。

详细操作：
1. 先准备服务端
   操作：在接收软件上启动 TCP 服务，并确认它监听的地址和端口。
   应看到：服务端已经启动等待连接。
2. 配置客户端
   操作：在北辰勾选 TCP，模式选择客户端，填写对方地址及端口；默认 6021 只是初始值。
   应看到：状态栏由连接中变为已连接。
3. 验证内容
   操作：发送一次，在服务端核对原始字符串、字段数和包尾；需要时再连续发送。
   应看到：服务端按行收到以 CRLF 结束的 GPCHC 报文。

常见问题与说明：
- 双方都选客户端时，没有监听者，连接会失败。
- 断线后目前不会自动重连，可暂停发送后重新调整连接设置。

08  TCP 服务端：等待客户端接入
让北辰监听所选网卡上的端口，并向连接者发送数据。

语音讲解原文：
传输控制协议 服务端：等待客户端接入。如果对方软件会主动连接北辰，就把北辰设置为服务端。服务端在所选网卡和端口上监听；看到客户端数量增加后再发送。多个客户端可以同时连接并接收同一句数据。若提示地址已占用，请换端口，而不是更换整张网卡。

详细操作：
1. 选择监听端
   操作：勾选 TCP，模式选择服务端，设置本机网卡和约定端口，例如 6021。
   应看到：状态栏显示服务端监听地址及零个连接。
2. 让对方接入
   操作：在对方软件填入北辰所选的本机 IP 和监听端口，主动连接。
   应看到：状态栏显示一个或多个连接。
3. 向连接者发报
   操作：确认存在连接后发送一次，随后按需要开启连续发送。
   应看到：每个已连接客户端均收到相同内容。

常见问题与说明：
- 同一台电脑上的两个 TCP 服务不能同时监听相同的 IP 和端口。
- 没有客户端时启用发送，不会凭空建立连接，应先检查连接数量。

09  发送频率、系统时间与回放速度
使用独立的全局报文时钟，统一普通发送和文件回放网络发送的 GPS 时间。

语音讲解原文：
全局报文时间与发送频率。全局时间控制对所有场景和回放网络发送生效，切换场景不会重置。系统时间适合正常联调；指定时间适合固定时刻、暂停或逐秒步进；保留原始则不替换场景和文件的时间。这里统一的是导航报文时间，行驶速度和文件回放倍速仍分别控制。修改日期后，软件自动计算导航周和周内秒。

详细操作：
1. 选择全局来源
   操作：在顶部全局报文时间选择系统当前时间、指定调试时间或保留原始时间。当前来源始终显示，切换场景不会改变它。
   应看到：所有场景的普通发送都使用同一来源；回放仅解析时仍显示文件原文。
2. 读取当前时刻
   操作：点击读取当前时刻，软件跟随本机时钟并自动换算 GPS 周和周内秒。
   应看到：来源显示系统时钟，GPS 周和周内秒持续更新。
3. 指定、暂停与步进
   操作：展开调试时间设置，可填写日期时刻或 GPS 周/秒。指定时刻可暂停、进退一秒，也可按倍率走时。参数输入和拖条都影响全局报文时间。
   应看到：暂停时所有新发报文的 GPS 时间相同；步进一秒后周内秒同步变化。
4. 回放同样生效
   操作：文件回放勾选网络发送后，发出的完整报文也应用全局时间。需要逐字发送原句或缺字段故障句时，选择保留原始时间。
   应看到：网络发出的时间与全局设置一致；无法替换的残缺报文会明确报错。
5. 区分三种速度
   操作：发送频率控制每秒条数，回放倍速控制文件播放节奏；全局时间倍率只控制 GPS 报文字段，不会改变车辆速度。
   应看到：例如 10 条/秒仍每 100 毫秒发一条，时间和运动可分别用于调试。

常见问题与说明：
- GPS = UTC + 18 秒为工具假定；系统时间早于 GPS 起点时仍会钳在非负周。
- 全局时间随配置保存。选择保留原始后，正常场景和文件使用各自时间，便于逐字复现。

10  从零完成一次快速测试
通过静止 RTK 场景建立最短的联调链路。

语音讲解原文：
静止场景自检。在完整配置中可以找到一键静止测试。先确认网卡和目标，再开始测试。这个自检会选择静止固定解并启动组播发送，但不会重置全局时间。第一次学习也可以在快速测试页选择直线场景，仅看演示，不发送任何网络数据。准备好连接自己的设备后，再点击开始测试。

详细操作：
1. 做好准备
   操作：确认网卡和目标；一键静止自检会启用组播并关闭 TCP，单播保留当前开关。全局时间保持你选择的来源，不被重置。
   应看到：所有仍启用的目标都属于本次联调范围。
2. 开始静止测试
   操作：在完整配置中点击“一键开始测试 · 静止 RTK”；新手也可在快速页先点击“仅看演示”，准备好后再开始发送。
   应看到：静止自检位置保持不动，速度为零；直线演示则能在地图上看到运动。
3. 检查再停止
   操作：核对发送记录与对端结果，点击“停止测试”。只看演示时点击“停止演示”。
   应看到：暂停后不再按频率生成普通发送记录。

常见问题与说明：
- 只选择场景卡片会更新预览，不会自动开始网络发送。
- 本机环回接收会让每次发送同时产生一条发送和一条接收记录。

11  理解十五组测试场景
区分协议基准、工况模拟、故障注入与典型运动。

语音讲解原文：
理解十五组测试场景。场景卡片不是简单的名字列表，每一组都代表一种待验证行为。协议原句用于比对字节，静止和低速用于正常工况，纯惯导与天线异常用于状态告警，故障集用于检查接收端容错。最后三组典型运动会让地图和输出报文一起变化。

详细操作：
1. 先看用途
   操作：切换完整配置可查看场景用途说明；依次了解初始化、RTK 浮点、纯惯导、后退和天线异常的不同状态。
   应看到：选中卡片和下方用途说明一起更新。
2. 逐字核对原句
   操作：选择“协议示例原句”，不启用系统时间或运动时，原句为 Status 61、Warning 0102、校验 4A。
   应看到：线上原文与协议示例一致。
3. 有目的地注入故障
   操作：选择故障集，检查超范围航向、非法纬度、非法告警值和强制错误校验；不要把这组当作正常导航输出。
   应看到：界面显示相应错误，接收端应按自身容错规则处理。

常见问题与说明：
- 故障集中附带的缺字段句子只是解析示例，不随主报文自动发出。
- 切换场景会替换当前字段；重要修改请先保存配置。

12  完整配置与字段编辑
认识时间、姿态、惯性、位置速度、状态和告警六组字段。

语音讲解原文：
完整配置与参数拖动。时间、姿态、位置和多数连续参数，都支持拖动条和精确输入。航向、俯仰与横滚按协议范围调整；经纬度拖条微调当前位置附近，文本仍能输入八位小数。速度、高度和惯性参数也有建议拖动范围。修改导航周或周内秒，会变成全局指定时间，而不是只改一个场景。运动自动更新的字段请先暂停再调整。

详细操作：
1. 展开完整字段
   操作：切换 Type 2，再展开“时间、姿态、位置”。
   应看到：GPS 时间、航向、俯仰、横滚、经纬度及高度输入框出现。
2. 按协议单位填写

   操作：暂停运动后，连续发送仍在进行，报文冻结在当前位置。再次开始会继续进度。修改运动参数或倍增倍数会从起点重新计算。

16  定位状态与十六位告警
读懂 Status 的十位个位，以及 Warning 的十六进制告警。

语音讲解原文：
定位状态与十六位告警。状态字段的十位表示卫星定位状态，个位表示系统模式。例如六一表示单点定位不定向与卫导模式，四二表示固定解与组合导航。告警字段使用四位十六进制，每一位对应一个开关。不要把四位十六进制告警当成普通十进制整数。

详细操作：
1. 解析状态
   操作：在完整配置中查看 Status；将两位数字分别对照协议约定的卫星状态和系统状态。
   应看到：状态含义与两位数字对应，不能把 61 当成一个没有分解的状态编号。
2. 解析告警
   操作：查看 Warning=0102，观察 bit1 和 bit8；正常无告警可使用 0000。
   应看到：0102 对应车辆轮速数据中断和副天线断路。
3. 检查场景一致性
   操作：定位丢失时同时检查星数、系统模式、告警位；后退场景检查速度与 bit12。
   应看到：字段之间能解释同一工况，而不是互相矛盾。

常见问题与说明：
- 告警位名称、阈值和时间约定以协议页为准，模拟器不会自动等待这些阈值再置位。
- 0000 只是告警全清，不代表实际接收端已经确认导航质量良好。

23  对端联调与故障排查顺序

语音讲解原文：
对端联调与故障排查顺序。对端收不到数据时，建议一层一层检查。先核对本机网卡与对端地址，再核对传输方式和端口，然后查看连接状态及发送备注，最后检查报文校验和字段。一次只改变一个条件，才能知道是哪一步解决了问题。

   操作：确认选中实际使用网卡，两端网络可达；若仅本机能收到组播，检查交换机组播设置和两端应用的防火墙放行。
   应看到：网络条件被逐项确认，而不是仅凭本机环回判断远端正常。
2. 传输层
   操作：单播确认接收端监听目标；组播确认加入同组同端口；TCP 确认一方服务端一方客户端及已连接状态。
   应看到：连接方向、地址和端口一致，发送备注没有无连接错误。
3. 报文层
   操作：核对 GPCHC 头、字段数、校验和包尾；对方按 CRLF 分行时检查是否收到完整一行。
   应看到：排除格式问题后，再判断数据语义。
4. 语义层
   操作：检查定位状态、星数、告警、经纬度格式和单位；先使用正常场景，再引入故障集。
   应看到：正常与异常工况有可对照结果，日志能说明问题发生时的原文。

常见问题与说明：
- TCP 断开暂无自动重连，重新连接后再发报。
- 不建议通过同时修改网卡、协议值、频率和端口来碰运气；保留前后日志便于比较。

24  完整联调练习与结果交付
把一次测试做成可复现、可交接的结果包。

语音讲解原文：
完整联调练习与结果交付。最后，把你的联调过程整理成一套可复现的材料。至少包含版本、网络配置、测试场景、预期结果、实际结果和原始日志。再准备一份配置和一份路径，别人就能按照同样条件复测。教程完成并不代表设备已经验收，验收还要以真实接收端的结果为准。

详细操作：
1. 记录基线
   操作：写明软件版本、对端软件版本、所选网卡、通道与端口；先完成静止正常工况。
   应看到：测试条件可以被别人准确复现。
2. 覆盖主要场景
   操作：至少测试正常静止、典型运动、状态告警和协议错误；对每项写下预期与实际结果。
   应看到：每个测试点都有对应日志与判断，而非只写“已测试”。
3. 保存交接材料
   操作：导出日志、保存配置和路径，将相关文件与测试记录放在一起。
   应看到：接收方可以恢复场景，并从原文核对结果。
4. 结束任务
   操作：停止普通发送、运动和文件回放；必要时关闭不再使用的网络通道，再退出软件。
   应看到：不再有意外持续发送，重要结果已经落盘。

常见问题与说明：
- 本教程的声音和文字可随时重播与搜索，完成后仍可按问题跳转到相应章节。
- 仿真结果只说明被测接口在当前测试条件下的表现，不替代真实设备、真实环境的验证。

25  规律运动：周期启停与蛇形行驶
从规律位置变化到速度、姿态变化，检查接收端是否持续跟踪。

语音讲解原文：
规律运动。除了直线、绕圈和八字，北辰还提供周期启停与正弦蛇形。周期启停重复加速、匀速、减速和停车，适合测试停车后重新启动。蛇形会规律地左右摆动，位置、速度、航向和角速度同步变化。先选择仅看演示，再观察地图和速度；准备好接收设备后，点击开始测试。全局时间与运动模型独立，暂停报文时间不会暂停车辆。

详细操作：
1. 选择规律场景
   操作：在快速页选择“周期启停”或“蛇形行驶”，点击“仅看演示”，先不发送网络数据。
   应看到：地图上显示运动位置与金色轨迹，已发出仍为零条。
2. 观察周期启停
   操作：选中周期启停，展开运动参数，将速度设为 10 米每秒，半径设为 20 米，观察四个阶段。
   应看到：速度会增加、保持、减小至零，再次启动；每周期前进约两倍半径。
3. 观察蛇形
   操作：选择蛇形行驶；调整半径控制左右摆幅，观察车辆方向和预计绿色路径。
   应看到：位置沿正弦轨迹前进，航向和转向角速度随弯曲方向变化。
4. 理解尺度与时间
   操作：地图选择自动适配；需要对端调试时保持全局时间设置，再点击开始测试。
   应看到：地图与发送报文使用同一真实位置；时间倍率只改变报文的 GPS 时间。

常见问题与说明：
- 半径决定模型几何尺度，并非真实车辆转向约束；模型用于可重复联调。
- 起步还会叠加加速度平滑过程，周期从模型运动进度计算。

26  故障注入：比例、随机与复现
让接收端在正常运动中遇到可控的异常，而不是手工修改整套场景。

语音讲解原文：
故障注入。展开故障注入，先选择方式、比例和故障形式，再启用开关。按比例模式累计分配，百分之十表示每一百条有效报文构造十条故障。随机模式对每条报文按概率选择，短时间内实际比例可能不同；保持种子和操作顺序，可以复现同一序列。故障只写入发送副本，不会改变真实运动或全局时钟。位置跳变以紫色标记，构造数量不代表对端已经收到。

详细操作：
1. 启用并选故障
   操作：展开故障注入，选择校验错误、丢失定位、位置跳变、时间滞后或速度异常，至少保留一种。
   应看到：界面列出选中的故障形式，正常场景和地图真实轨迹保持独立。
2. 按比例测试
   操作：选择按比例均匀注入，将比例拖到 10%，启用后发送一百条有效结构报文。
   应看到：累计构造十条故障；故障类型在所选项目中轮换，统计显示处理数与跳过数。
3. 随机并复现
   操作：选择随机概率注入，输入种子，点击计数归零并重放随机序列，再使用相同顺序发送。
   应看到：相同种子、设置与报文序列产生相同注入选择；少量报文的比例可能偏离目标。
4. 对照地图和原文
   操作：注入位置跳变并发送一次，查看地图紫色点；展开收发记录，对比发送原文与原始场景。
   应看到：故障位置与正常位置可以同时显示，原始场景参数未被故障覆盖。
5. 收尾与保存
   操作：停止测试后关闭故障开关，需要复用时保存配置；复核日志中的故障注入说明。
   应看到：关闭后恢复正常发送；保存配置能恢复模式、比例、种子和选择的故障。

常见问题与说明：
- 时间滞后故障在全局时间之后回退十秒，用于接收端过期数据判断。
- 统计是发送前构造数；无效或不适用报文会明确跳过，网络失败不代表对端收到。

27  四地离线地图与自动缩放
在北京、达茂旗、湛江、广州的真实开源测试区域开展模拟。

语音讲解原文：
四地离线地图。选择北京、达茂旗、湛江或广州，软件会加载随包提供的真实开源地图，并将模拟起点移到该区域。每份数据只覆盖当地约两到三公里的选定测试范围，不是整座城市。自动适配会同时容纳当前位置、预计路径、已行轨迹和故障点，并显示距离比例。全部坐标使用 W G S 八十四。地图仅供模拟联调，越界时会提示，不会联网请求更多地图。

详细操作：
1. 选择区域
   操作：在地图上方选择北京、达茂旗、湛江或广州；区域切换会停止当前发送并重设起点。
   应看到：地图加载当地道路与水域等真实数据，经纬度移到区域中心。
2. 设置并开始
   操作：选择规律运动场景，确认区域仍保持，再点击仅看演示或开始测试。
   应看到：新场景仍从当前选择的区域出发，地图与报文位置一致。
3. 使用自动比例
   操作：将地图视野设为自动适配，观察地图下方距离比例和车辆附近轨迹。
   应看到：当前位置、轨迹及故障点处于合适视野；低速运动会自动放大观察。
4. 回到区域中心
   操作：若测试位置超出数据范围，先保存需要的轨迹，再点击“在此区域开始”。
   应看到：发送和回放停止、旧轨迹清空，当前位置回到区域中心。
5. 查看来源
   操作：查看地图署名和版权说明；需要自行重建数据时参考仓库中的地图下载脚本与来源文档。
   应看到：地图注明 OpenStreetMap 贡献者及 ODbL 许可，支持完全离线加载。

常见问题与说明：
- 达茂旗选取百灵庙镇附近；四地均为小范围摘录，并非全市或全旗覆盖。
- 底图为 WGS84 数据，不与其他坐标系瓦片混用。手动输入地点时也应使用 WGS84。

28  增量升级：校验、启用与回退
首次安装新版完整包后，后续仅导入对应基础版本的应用增量包。

语音讲解原文：
增量升级。旧版没有升级入口，需要先运行一次支持升级的新完整版。以后从可信发布页下载与你当前版本对应的增量包，在软件里选择导入，核对基础版本、目标版本和校验值，再确认安装。安装只暂存新版本，不会立刻打断当前任务；保存配置并停止测试后重启启用。新版本无法正常启动时会自动回退。升级不重复打包浏览器运行时，不变的地图和语音也不会进入增量包。

详细操作：
1. 确认基础版本
   操作：展开软件升级，查看当前版本，从可信发布页下载匹配此基础版本的 .bcu 文件。
   应看到：版本应与增量包要求一致；旧版 0.7 需要先安装新版完整版。
2. 选择并核对
   操作：点击选择增量包，在原生文件窗口选择文件，再核对目标版本、文件数、体积与 SHA256。
   应看到：只展示预览，不自动安装；不匹配或损坏的包会给出明确错误。
3. 安装到暂存目录
   操作：确认来源与校验值正确后点击确认安装，等待完成提示。
   应看到：软件写入新目录并完整校验，当前应用文件保持可用，界面提示等待重启。
4. 保存并重启
   操作：先保存需要的配置或日志，再点击重启使用新版本；重启后检查当前版本和时间设置。
   应看到：新版本完成界面初始化后确认启用；失败会在约三十秒后重启回退。
5. 需要时回退
   操作：如升级后的业务行为不适合当前联调，停止测试后点击回退上一版本。
   应看到：重新启动此前版本，用户配置与导出的日志、路径不会被升级删除。

常见问题与说明：
- 增量包含应用代码，只使用可信发布来源；SHA256 是完整性校验，不是发布者签名。
- 更换 Electron 运行时或升级引导程序需要完整包；增量包只能用于它明确要求的基础版本。
