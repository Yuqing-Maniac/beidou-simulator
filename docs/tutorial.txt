01  认识北辰与学习方式
先认识模拟器的边界，再选择适合自己的学习方式。

语音讲解原文：
认识北辰与学习方式。欢迎使用北辰导航模拟器。本教程可以完全离线使用，每一章都有中文讲解、操作步骤和结果检查。教程只会定位界面，不会替你修改参数或发送报文。你可以先听，再按步骤操作；也可以关闭语音，只阅读文字。已有的收发任务不会因打开教程而自动停止。

详细操作：
1. 选择学习入口
   操作：点击顶部“语音教程”开始逐章学习；点击“使用说明”可搜索章节、查看全文或下载文字教程。
   应看到：右下角显示教程面板，当前章节和语音字幕清晰可见。
2. 掌握语音控制
   操作：使用播放、暂停、重播和音量控制；需要连续学习时打开“讲完自动下一章”。
   应看到：暂停后停在当前语音位置，重播从当前章开头播放。
3. 边学边操作
   操作：点击步骤旁“定位”，观察金色框所指控件；可以收起面板，再自行操作真实界面。
   应看到：定位只改变视图和高亮，不会自动触发发送。

常见问题与说明：
- 文字步骤比语音更详细，操作时以“应看到”作为检查标准。
- 切换章节不会修改你的网络或数据；关闭教程会恢复进入时的界面模式。

02  下载、运行与版本确认
完成首次运行，了解便携版、存档和兼容范围。

语音讲解原文：
下载、运行与版本确认。先确认下载的是当前版本的便携程序。单文件版本可以直接运行，压缩包版本必须完整解压，不能只拿出一个程序文件。软件自带运行环境，教程语音也已经打包，不需要联网获取中文语音。运行资源保持完整，优先保证兼容性。

详细操作：
1. 选择安装包
   操作：从当前 Release 或提供的 Drive 链接下载 Windows x64 便携 EXE；若下载 ZIP，请全部解压到本机硬盘。
   应看到：EXE 可直接启动；ZIP 目录中的程序与资源保持在一起。
2. 核对版本
   操作：查看“使用说明”标题中的版本号；下载旁的 SHA256SUMS 可用于核对安装包。
   应看到：版本应与下载文件名一致，不要混用新旧目录中的资源。
3. 了解数据保存
   操作：配置和路径可保存到本机，同时导出 JSON。重要设置请保留导出文件，再升级或换电脑。
   应看到：重新运行后可恢复本机配置，且不会自动开始发送。

常见问题与说明：
- 浏览器运行与桌面运行的本机存储相互独立。
- Windows Server 2022 的打包检查不代表所有 Windows 与麒麟机器都已实测。

全屏、启动声音与界面导航。桌面版默认全屏启动，开场动画约两点五秒。按功能键十一或点击顶部全屏按钮，可以回到普通窗口。快速测试适合直接选场景，完整配置用于修改全部字段。协议约定用来查询定义，开场回看只重播动画，不重置场景。

04  网卡选择与共享使用
选对实际连接的 IPv4 网卡，理解网卡共享与端口冲突的区别。

语音讲解原文：
网卡选择与共享使用。顶部三种连接共用一张网卡。请选择与接收设备处在同一网络的本机地址，不要把对方设备地址填到网卡选择里。选择网卡只是确定收发来源，不会独占整张网卡，也不会更改系统网络设置。组播可以共享端口，但另一个软件也要允许复用。

详细操作：
1. 辨认本机地址
   操作：展开“共用网卡”，根据网线或无线网络实际使用的本机 IPv4 地址选择；本机回环地址只适合回环测试。
   应看到：所选地址属于本机，而不是对方接收设备。
2. 核对两端网络
   操作：确认本机与对端地址可在同一网络互通；多网卡电脑不要误选未连接的虚拟或备用网卡。
   应看到：发送记录中的来源网卡与你选择的地址一致。
3. 理解共享限制
   操作：多个软件可共用同一张网卡。若要共享组播端口，两方都需开启地址/端口复用；TCP 服务端不能共享同一监听 IP 和端口。
   应看到：端口占用错误只针对某个端口，不代表整张网卡被占用。

常见问题与说明：
- 修改网卡或连接设置会重新建立收发连接，连续任务中操作前应先暂停。
- 本机可同时运行其他网络应用，组播收包仍取决于交换机、路由和防火墙。

05  UDP 组播：一份数据给多个接收端
设置组播地址和端口，完成本机环回接收。

语音讲解原文：
用户数据报协议 组播：一份数据给多个接收端。组播适合把同一条导航报文送给多个接收端。默认组播地址是二二四点一百点一百点一，端口六零二零。两端必须使用相同的组播地址与端口，接收端还需要加入组播组。软件打开本机环回，因此自己发出的组播也可以在报文流中看到。

详细操作：
1. 开启组播
   操作：勾选 UDP 组播；将地址设置为 224.100.100.1，端口设置为 6020，或填写联调双方约定值。
   应看到：状态栏出现当前组播目标；配置正确时没有加入组播失败提示。
2. 设置接收端
   操作：在对方软件上选择实际网卡，并加入同一组播地址和端口。不要把组播当作普通单播地址使用。
   应看到：对方开始监听后，可以收到同一组播组内的导航数据。
3. 单次验证
   操作：选择“协议示例原句”，先不要启用系统时间或运动，再点击“发送一次”。
   应看到：报文流出现发送记录；组播环回正常时还会出现接收记录。

常见问题与说明：
- 仅仅能在本机环回收到，并不能证明对端已经收到。
- 修改为普通单播地址后，组播加入可能失败；单播应使用独立的 UDP 单播配置。

06  UDP 单播：精确发送到一个对端
配置独立单播目标，也可与组播同时发送。

语音讲解原文：
用户数据报协议 单播：精确发送到一个对端。单播是把数据直接送到一个设备的地址和端口。这里填写的是对方地址，不是本机网卡地址。单播、组播和传输控制协议可以独立启用，也可以同时开启；发出的内容是同一句导航报文。单播没有连接握手，发送记录并不等于对方已经确认收到。

详细操作：
1. 填写单播目标
   操作：勾选 UDP 单播，将对端地址改为接收设备 IPv4，端口改为对方实际监听端口。
   应看到：单播目标与接收端的监听配置一致。
2. 先独立验证
   操作：初次联调可先关闭组播和 TCP，仅保留单播，然后发送一次；本机测试可把对端设成本机地址并用另一个 UDP 工具监听。
   应看到：另一接收工具收到完整的 GPCHC 原文。
3. 启用多路输出
   操作：单播验证后可同时打开组播；检查发送备注中的通道列表。
   应看到：同一句报文同时经过组播和单播输出。

常见问题与说明：
- 单播配置是发送目标，不会自动在该端口新开一个单播接收服务。
- UDP 没有送达确认，请以接收端记录作为最终证据。

07  TCP 客户端：连接已有服务端
让北辰作为主动连接的一方，向已有服务端发送数据。

语音讲解原文：
传输控制协议 客户端：连接已有服务端。当接收软件已经在监听端口时，北辰应选择客户端模式。填写接收软件的地址和监听端口，再开启连接。请先看到已连接状态，再发送报文；如果界面显示无连接，发送备注里的错误不能忽略。连接会使用顶部所选的本机网卡。

详细操作：
1. 先准备服务端
   操作：在接收软件上启动 TCP 服务，并确认它监听的地址和端口。
   应看到：服务端已经启动等待连接。
2. 配置客户端
   操作：在北辰勾选 TCP，模式选择客户端，填写对方地址及端口；默认 6021 只是初始值。
   应看到：状态栏由连接中变为已连接。
3. 验证内容
   操作：发送一次，在服务端核对原始字符串、字段数和包尾；需要时再连续发送。
   应看到：服务端按行收到以 CRLF 结束的 GPCHC 报文。

常见问题与说明：
- 双方都选客户端时，没有监听者，连接会失败。
- 断线后目前不会自动重连，可暂停发送后重新调整连接设置。

08  TCP 服务端：等待客户端接入
让北辰监听所选网卡上的端口，并向连接者发送数据。

语音讲解原文：
传输控制协议 服务端：等待客户端接入。如果对方软件会主动连接北辰，就把北辰设置为服务端。服务端在所选网卡和端口上监听；看到客户端数量增加后再发送。多个客户端可以同时连接并接收同一句数据。若提示地址已占用，请换端口，而不是更换整张网卡。

详细操作：
1. 选择监听端
   操作：勾选 TCP，模式选择服务端，设置本机网卡和约定端口，例如 6021。
   应看到：状态栏显示服务端监听地址及零个连接。
2. 让对方接入
   操作：在对方软件填入北辰所选的本机 IP 和监听端口，主动连接。
   应看到：状态栏显示一个或多个连接。
3. 向连接者发报
   操作：确认存在连接后发送一次，随后按需要开启连续发送。
   应看到：每个已连接客户端均收到相同内容。

常见问题与说明：
- 同一台电脑上的两个 TCP 服务不能同时监听相同的 IP 和端口。
- 没有客户端时启用发送，不会凭空建立连接，应先检查连接数量。

09  发送频率、系统时间与回放速度
区分普通连续发送的频率、GPS 时间和文件回放倍速。

语音讲解原文：
发送频率、系统时间与回放速度。发送频率表示普通连续发送时，每秒发出多少条报文。十条每秒，就是大约每一百毫秒发一条。它与文件回放的倍速是两套控制。使用系统时间后，每次发送会更新导航报文的周和周内秒；关闭后使用场景或手工填写的时间。

详细操作：
1. 设置普通频率
   操作：在顶部输入 10，观察旁边说明；输入 20 时应显示每 50 毫秒发送一条。
   应看到：频率与间隔说明相互对应。
2. 使用实时钟
   操作：需要真实流动的时间时勾选“使用系统时间”；需要逐字比对示例时先取消勾选。
   应看到：启用后每条发送报文的 GPS 周与周内秒来自本机时钟。
3. 区分三种时间
   操作：GPS 周从 1980-01-06 起算；GPS 周内秒从本周日零点起算；本工具按 GPS=UTC+18 秒换算。
   应看到：协议字段展示的是 GPS 时间，而不是直接写入北京时间。

常见问题与说明：
- 18 秒是工具换算假定，协议表未规定闰秒。
- 普通定时器不保证硬实时精度；文件回放速度由回放滑条控制。

10  从零完成一次快速测试
通过静止 RTK 场景建立最短的联调链路。

语音讲解原文：
从零完成一次快速测试。第一次联调建议先用静止场景排除运动因素。确认网卡和组播目标后，点击一键开始测试。软件会加载静止固定解场景，启用系统时间与组播连续发送。观察报文流和地图，再点击暂停结束。测试按钮会真正发送网络报文，请在你准备好时自行点击。

详细操作：
1. 做好准备
   操作：确认目标地址、端口和网卡；知道“一键开始测试”会启用组播与系统时间、关闭 TCP，原有单播开关仍以当前设置为准。
   应看到：所有仍启用的目标都属于本次联调范围。
2. 开始静止测试
   操作：点击“一键开始测试 · 静止 RTK”，观察发送按钮变成暂停。
   应看到：地图位置保持静止，速度为零，状态为 RTK 稳定解组合导航。
3. 检查再停止
   操作：核对发送与接收记录、接收端状态，点击暂停。
   应看到：暂停后不再按频率生成普通发送记录。

常见问题与说明：
- 只选择场景卡片会更新预览，不会自动开始网络发送。
- 本机环回接收会让每次发送同时产生一条发送和一条接收记录。

11  理解十三组测试场景
区分协议基准、工况模拟、故障注入与典型运动。

语音讲解原文：
理解十三组测试场景。场景卡片不是简单的名字列表，每一组都代表一种待验证行为。协议原句用于比对字节，静止和低速用于正常工况，纯惯导与天线异常用于状态告警，故障集用于检查接收端容错。最后三组典型运动会让地图和输出报文一起变化。

详细操作：
1. 先看用途
   操作：切换完整配置可查看场景用途说明；依次了解初始化、RTK 浮点、纯惯导、后退和天线异常的不同状态。
   应看到：选中卡片和下方用途说明一起更新。
2. 逐字核对原句
   操作：选择“协议示例原句”，不启用系统时间或运动时，原句为 Status 61、Warning 0102、校验 4A。
   应看到：线上原文与协议示例一致。
3. 有目的地注入故障
   操作：选择故障集，检查超范围航向、非法纬度、非法告警值和强制错误校验；不要把这组当作正常导航输出。
   应看到：界面显示相应错误，接收端应按自身容错规则处理。

常见问题与说明：
- 故障集中附带的缺字段句子只是解析示例，不随主报文自动发出。
- 切换场景会替换当前字段；重要修改请先保存配置。

12  完整配置与字段编辑
认识时间、姿态、惯性、位置速度、状态和告警六组字段。

语音讲解原文：
完整配置与字段编辑。完整配置可以按字段构造你需要的导航状态。展开时间姿态位置后，可以修改经纬度和航向；下面还有三轴惯性、速度、卫星状态及告警。修改合法字段会重新生成报文和校验，但开启系统时间或运动后，相关自动字段会被实时更新。

详细操作：
1. 展开完整字段
   操作：切换 Type 2，再展开“时间、姿态、位置”。
   应看到：GPS 时间、航向、俯仰、横滚、经纬度及高度输入框出现。
2. 按协议单位填写
   操作：航向精确到两位，经纬度线上保留八位，高度两位，加速度四位；未规定的单位不能自行当成协议要求。
   应看到：字段提示与协议约定页一致，格式问题以红色提示。
3. 避免自动覆盖
   操作：手工调试时间时关闭系统时间；手工调整位置、姿态或速度时先暂停运动。
   应看到：暂停自动更新后，手工值保持稳定。

常见问题与说明：
- 平面速度应与东向、北向速度的合速度一致；界面提示可辅助检查。
- 系统保留故障测试能力，部分格式告警不会阻止发送。

13  三种经纬度格式的显示和输入
在小数度、度分秒、度分千分之间切换并输入坐标。

语音讲解原文：
三种经纬度格式的显示和输入。坐标的显示和输入格式是联动的。小数度可以直接输入八位小数；度分秒依次填写度、分和秒；度分千分依次填写度和带三位小数的分。分和秒都不能达到六十，南纬与西经可以使用负号或方向字母。切换格式只改变读写方式，内部精度会保留。

详细操作：
1. 输入小数度

16  定位状态与十六位告警
读懂 Status 的十位个位，以及 Warning 的十六进制告警。

语音讲解原文：
定位状态与十六位告警。状态字段的十位表示卫星定位状态，个位表示系统模式。例如六一表示单点定位不定向与卫导模式，四二表示固定解与组合导航。告警字段使用四位十六进制，每一位对应一个开关。不要把四位十六进制告警当成普通十进制整数。

详细操作：
1. 解析状态
   操作：在完整配置中查看 Status；将两位数字分别对照协议约定的卫星状态和系统状态。
   应看到：状态含义与两位数字对应，不能把 61 当成一个没有分解的状态编号。
2. 解析告警
   操作：查看 Warning=0102，观察 bit1 和 bit8；正常无告警可使用 0000。
   应看到：0102 对应车辆轮速数据中断和副天线断路。
3. 检查场景一致性
   操作：定位丢失时同时检查星数、系统模式、告警位；后退场景检查速度与 bit12。
   应看到：字段之间能解释同一工况，而不是互相矛盾。

常见问题与说明：
- 告警位名称、阈值和时间约定以协议页为准，模拟器不会自动等待这些阈值再置位。
- 0000 只是告警全清，不代表实际接收端已经确认导航质量良好。

17  原文、校验与报文解析

   操作：点击十六进制，检查末尾 0d 0a；界面原文中的反斜线表示只用于展示。

   操作：打开协议约定，查字段、单位、范围、小数位及告警枚举。
   应看到：不确定的单位标注为未规定，而不是误当成设备强制要求。

常见问题与说明：
- 修改字段后会重新计算校验；故障集可以故意覆盖校验。

23  对端联调与故障排查顺序
按网络、连接、原文、字段四层排查，不盲目同时修改。

语音讲解原文：
对端联调与故障排查顺序。对端收不到数据时，建议一层一层检查。先核对本机网卡与对端地址，再核对传输方式和端口，然后查看连接状态及发送备注，最后检查报文校验和字段。一次只改变一个条件，才能知道是哪一步解决了问题。

详细操作：
1. 网络层
   操作：确认选中实际使用网卡，两端网络可达；若仅本机能收到组播，检查交换机组播设置和两端应用的防火墙放行。
   应看到：网络条件被逐项确认，而不是仅凭本机环回判断远端正常。
2. 传输层
   操作：单播确认接收端监听目标；组播确认加入同组同端口；TCP 确认一方服务端一方客户端及已连接状态。
   应看到：连接方向、地址和端口一致，发送备注没有无连接错误。
3. 报文层
   操作：核对 GPCHC 头、字段数、校验和包尾；对方按 CRLF 分行时检查是否收到完整一行。
   应看到：排除格式问题后，再判断数据语义。
4. 语义层
   操作：检查定位状态、星数、告警、经纬度格式和单位；先使用正常场景，再引入故障集。
   应看到：正常与异常工况有可对照结果，日志能说明问题发生时的原文。

常见问题与说明：
- TCP 断开暂无自动重连，重新连接后再发报。
- 不建议通过同时修改网卡、协议值、频率和端口来碰运气；保留前后日志便于比较。

24  完整联调练习与结果交付

语音讲解原文：
完整联调练习与结果交付。最后，把你的联调过程整理成一套可复现的材料。至少包含版本、网络配置、测试场景、预期结果、实际结果和原始日志。再准备一份配置和一份路径，别人就能按照同样条件复测。教程完成并不代表设备已经验收，验收还要以真实接收端的结果为准。

详细操作：
1. 记录基线
   操作：写明软件版本、对端软件版本、所选网卡、通道与端口；先完成静止正常工况。
   应看到：测试条件可以被别人准确复现。
2. 覆盖主要场景
   操作：至少测试正常静止、典型运动、状态告警和协议错误；对每项写下预期与实际结果。

4. 结束任务
   操作：停止普通发送、运动和文件回放；必要时关闭不再使用的网络通道，再退出软件。
   应看到：不再有意外持续发送，重要结果已经落盘。
