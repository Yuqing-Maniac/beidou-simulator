# 北辰离线增量升级

从包含升级引导程序的完整版本开始，北辰可以导入 `.bcu` 应用增量包。旧版 0.7 没有升级引导程序，必须先安装一次新版完整 EXE 或 ZIP。后续应用代码、教程和地图变化可只发增量包；更换 Electron 主版本、平台、架构或引导程序仍需完整安装包。

## 用户操作

1. 从可信的北辰 GitHub Release 下载与当前版本对应的 `.bcu` 及 SHA256 校验文件。升级包包含可执行应用代码，请只使用可信发布者提供的包。
2. 在软件内选择“导入增量升级包”。选择后仅预览，不会立即替换或重启。
3. 核对基础版本、目标版本、变化文件数和 SHA256。只有当前应用文件与基础版本完全匹配时才能安装。
4. 安装后保存正在调试的配置，停止发送和回放，再点击“重启并完成升级”。也可退出后下次启动生效。
5. 若新版本无法正常完成界面初始化，程序会在约 30 秒后重新启动并回退。也可使用“回退上一版本”。用户配置、日志和保存的路径不属于增量文件范围。已保存的配置、路径和教程偏好额外镜像到固定的 userData 文件，不依赖 file:// 地址或临时解压路径；升级重启前和正常退出时同步，正常运行时每秒同步变化。

增量包只替换软件层：不会重复携带 Electron 浏览器运行时，不变的语音和地图文件也不进入包。每个包严格对应一个基础版本，不能跳过要求的基础版本；发布者也可从较早版本直接制作对应的跨版本包。

为了保护升级事务，新版使用单实例运行：重复打开同一软件会唤起已打开的窗口。运行软件所用的 Windows 用户不同，则各自的配置和升级记录独立。

## 便携 EXE 与持久化

electron-builder 的便携 EXE 每次启动可能解压到不同的临时路径，因此不能覆盖临时的 `resources/app.asar`。北辰将验证后的完整应用层快照保存在 Electron `userData/application-updates/releases/`，通过固定引导程序选择活动快照，原始完整 EXE 保留作为回退基础。活动快照绑定原始完整包的版本、文件清单和运行时身份；打开更新的完整包时会使用新完整包，旧快照不会覆盖它。后续启动仍打开原来的 EXE 即可；无需保留下载的 `.bcu` 文件。

安装采用“新目录暂存 → 全量文件校验 → 原子记录待启用版本”的过程，不会原地覆盖正在运行的文件。首次运行待启用版本时记录试运行标志，只有界面完成初始化并主动确认健康才正式启用。若试运行中途崩溃，下一次启动使用此前已确认的版本。前一快照保留供手动回退。

校验包括压缩包大小限制、路径范围、文件 SHA256、精确基础版本和文件清单、平台、架构、Electron 主版本及不变的引导程序。SHA256 用于完整性检查，不等同于发布者数字签名；用户仍应核对可信 Release 提供的校验文件。

## 发布者制作增量包

先完整打包并验证目标版本。保存每个已发布版本 ZIP 中的 `resources/app.asar`，以这两个真实打包产物制作增量包：

```bash
node scripts/build-update.cjs \
  --base previous/resources/app.asar \
  --target release/win-unpacked/resources/app.asar \
  --platform win32 --arch x64 --electron-major 22 \
  --out release/beichen-0.8.0-test-to-0.8.1-test-win-x64.bcu
```

也支持已解压的应用目录，但两边必须与实际交付的 app.asar 内容完全一致，不能混用源代码目录与打包产物。脚本输出 `.bcu`、`.bcu.sha256`，并报告变化文件数、体积和 SHA256。应同时保存目标完整包，供首次安装、基础不匹配及运行时更新使用。

`electron/main.cjs`、`electron/update-runtime.cjs` 和 `electron/update-storage.cjs` 是引导程序，增量包不允许改变它们；窗口、网络和业务逻辑在 `electron/app-entry.cjs` 等应用文件中，可以随增量包更新。增量包包含新增及修改文件，删除列表和完整目标清单；不变的文件从当前应用复制到新快照。

## 验证

```bash
node --test test/update.test.cjs
```

覆盖只携带变化文件、正确应用/删除、便携临时目录迁移、健康确认、失败回退、用户配置保留、文件篡改、路径穿越、符号链接、版本及运行时不匹配、引导程序变化与待重启重复安装。

Windows 打包后可额外运行 `node scripts/windows-update-smoke.cjs release/win-unpacked`。它仅在临时复制的应用中指定隔离 userData，实际执行增量安装、健康确认、跨文件路径设置恢复和故意失败版本的自动回退；不会给交付应用加入测试后门。

Windows 发布工作流支持可选输入 `base_tag`。为空时构建首个完整版本；填写已发布且含同一引导程序的基础 tag 后，自动下载该版完整 ZIP，以两个真实 app.asar 制作增量包，重建校验与目标包完全一致后再发布 `.bcu` 和 SHA256。用户日常只需下载 `.bcu`，完整 ZIP/EXE 保留供首次安装、跨运行时升级和恢复使用。
